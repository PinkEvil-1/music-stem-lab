# 可行性與案例分析

日期：2026-11-09。桌面研究完成；所有本地實驗為 NOT_RUN。來源編號對應 08 文件。

## 能做到什麼

去人聲、依樂器類別分軌及重新混成缺少某樂器的伴奏，已有可用的研究與開源推論路徑。
候選 Demucs 六軌模型含 guitar／piano；RoFormer 類框架也可納入候選比較。這只證明有技術路徑，不證明任意權重能符合本專案音質要求。[S001、S002]

現行需求依所選模型／權重原生提供的類別與軌數處理，不增加模型沒有提供的軌。同一類別的多個樂器以該類別整體輸出；包含多把吉他的歌曲仍可測試 guitar 整體移除品質，不要求分辨主奏、節奏或演奏者。逐把分離研究已依 D013 取消。

## 去吉他演算法候選：工程提案

候選 A：同一模型估計所有類別，混合非吉他 stems。
候選 B：以原始混音 x 減去對齊且增益一致的 guitar 估計 g，得到 x − g。
先比較兩者對非目標音色、相位及殘留的影響，再由 T014 決定。

B 在代數上保留「x = g + (x − g)」，但不代表聲學上完美消除；g 可能漏掉吉他或帶走其他聲音。
A 可能放大各軌估計誤差，不能假設模型各軌加總一定等於輸入。
避免不同模型或獨立增益處理後直接相減。內部用浮點 PCM，共用時基、取樣率與聲道；播放匯出使用有紀錄的共同增益，避免逐軌正規化改變相對音量。

## 候選與取捨

- Demucs 作為容易建立比較基準的候選，先評估四軌去人聲及六軌去吉他；上游原 repository 已封存，須評估相容性與維護風險。[S001]
- Music-Source-Separation-Training 支援多種架構，適合比較替代路徑；框架支援不等於具備已驗證的 guitar 權重。[S002]
- 不先訓練新模型。只有可用權重與音質都不符合時，再估算資料、授權及訓練成本。
- yt-dlp／FFmpeg 可作來源取得與音訊處理候選；來源網站變動及必要執行環境須固定版本並實際測試。[S003]

## 發布與品質風險

來源下載須同時考慮音樂權利與 YouTube 平台允許的使用方式；有音樂著作權人的授權不等於已滿足平台下載限制。
來源取得設計為可替換 adapter，規劃合法本地音訊測試入口，避免分離實驗依賴線上下載可用性。[S005]

本文件不含成功分離的聲音範例；現行案例為 C001–C006、C009–C013，模型測試尚未執行。C007、C008 為已取消歷史案例。
