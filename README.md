# Music Stem Lab

Music Stem Lab 規劃提供個人使用的音樂分軌網站：貼上 YouTube 網址，取得音訊、移除人聲或吉他，並儲存分軌與伴奏檔案。多筆工作依序排隊，方便製作樂器練習用伴奏。

目前處於規格草案與技術驗證規劃階段，repository 僅包含文件，尚無可執行的網站或音訊處理程式。

## 功能規劃

| 範圍 | 目標 | 目前狀態 |
| --- | --- | --- |
| 網址與音訊取得 | 接收單筆或多筆 YouTube 網址，取得可處理的音訊 | 規格草案完成，待驗證與實作 |
| 去人聲 | 輸出人聲軌與無人聲伴奏 | 技術路徑已分析，音質尚未實測 |
| 去吉他 | 輸出吉他軌與無吉他伴奏，保留人聲及其他樂器 | 案例已分析，音質尚未實測 |
| 分軌保存 | 保存來源、分軌、伴奏與處理資訊，支援試聽及下載 | 規格草案完成，待實作 |
| 排隊處理 | 持久化 FIFO 佇列，同時執行一筆完整工作 | 流程已規劃，待實作 |
| 取消與恢復 | 取消、失敗重試、程序重啟後恢復 | 流程已規劃，待實作 |
| 多樂器分軌 | 依模型能力輸出鼓、bass、鋼琴等類別 | 延伸需求，待模型驗證 |
| 逐把吉他分離 | 將同一首歌中的各把吉他獨立成軌 | 研究項目，不納入第一版承諾 |

完整需求、優先級及驗收對應見 [產品規格](docs/01-PRODUCT-SPEC.md)；開發狀態以 [任務追蹤](docs/06-TASKS.md) 為準。

## 吉他處理範圍

第一版草案將多把一般吉他合併為 guitar 類別，一起移除。只移除其中一把主奏或節奏吉他，需要額外研究與驗證。

目前建議把低音吉他歸為 bass，在去吉他時保留；此分類仍待確認。分離結果可能有目標音殘留或其他樂器受損，不能保證還原錄音室原始軌。案例與限制見 [可行性分析](docs/02-FEASIBILITY.md)。

## 預期使用流程

貼上網址 → 選擇模式 → 提交佇列 → 依序取得音訊與分離 → 驗證並儲存 → 試聽與下載。

上述為待實作流程。排隊、取消、重試及異常恢復的詳細行為見 [工作流程規格](docs/04-WORKFLOWS.md)。

## 開發方式與下一步

本專案採規格驅動開發，使用需求 ID、驗收案例與任務 ID 追蹤每項工作：

需求 → 驗收條件 → 任務 → 實作 → 驗證證據 → 更新狀態與交接紀錄。

目前已完成規格文件、案例分析、候選架構與技術驗證計畫；尚未盤點硬體、安裝依賴、下載模型、執行音訊實驗或開發網站。

下一步為 T010 環境盤點，接著驗證去人聲與去吉他的品質及資源需求，再確定技術堆疊並進入實作。Python API、SQLite、單一 worker 與本地磁碟是目前候選方案，尚未定案。驗證方法見 [技術驗證計畫](docs/05-VALIDATION-PLAN.md)。
